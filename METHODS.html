Standalone IDtracker.ai post-processing: version 0.8.1

This document describes every calculation performed by processor.py. The script intentionally performs no other behavioral, geometric, or temporal analyses.

Scientific safeguard. A missing interval or an interval starting at global frame 0 is not repaired automatically. The GUI requires a positive, researcher-approved global entry frame before processing. No coordinates are interpolated, smoothed, or carried forward by this prototype. The only optional coordinate replacement is the explicitly enabled social-disappearance substitution documented below. Validated and without-gaps IDtracker files are preferred; a clearly labeled raw IDtracker fallback is used when they are absent.

Analysis window and frame convention

The analysis begins at the researcher-approved global entry frame. The requested timespan, which defaults to 7200 frames, is added to that start to obtain the inclusive global end frame. Both the start and end frames are analyzed.

For example, a start frame of 62 and a requested timespan of 7200 produce an inclusive end frame of 7262. This represents 7200 intervals between frames and 7201 frame observations. The mathematical notation for this convention is collected in the appendix at the end of this document.

Human-approved disturbance adjustment and provenance

The Jump Audit examines every newest eligible BA and fight session with usable positive start evidence and groups evidence by source video. A final approved start is preferred. If a video is deliberately held for manual start review, one positive, unambiguous detected interval may be used provisionally for the read-only audit. Zero, missing, and conflicting detected intervals remain excluded. A provisional audit start never authorizes processing.

The audit never changes an analysis start automatically. A video-level recommendation appears in a separate GUI tab and becomes the final start only after the researcher selects the video and clicks Approve selected start recommendation.

The analysis-ready columns near the front of the combined CSV are analysis_start_frame and analysis_end_frame_inclusive. They contain the final approved decision used in calculations. The original start and decision history are retained near the end as archived_original_start_frame, start_frame_decision_source, and start_frame_decision_provenance. The detailed video and animal-track evidence is saved separately in timestamped Jump Audit CSV files, so the main statistical table is not overloaded with diagnostic columns.

Reusable settings and decision restoration

The GUI can save one versioned JSON bundle containing the visible connection paths, analysis parameters, SLURM settings, every positive session start with its archived original and decision provenance, and the current Jump Audit video and track tables. The private SSH key itself is never copied; only its configured filesystem path is stored. JSON settings default to ~/Downloads/IDtracker_postprocessing_results/saved_settings/.

The loader also accepts prior combined-results CSV files and Jump Audit video-summary CSV files. A combined CSV restores the common calculation parameters and deduplicates the two animal rows of a fight by qc_record_id. A Jump Audit video CSV loads its sibling track CSV when present. Only a video row whose saved decision is exactly APPROVED can restore its suggested start; pending recommendations remain display-only. Loading a separate Jump Audit CSV supplements any previously queued combined-CSV decisions rather than replacing them.

Saved session starts are matched first by exact discovered session record ID. If that run has since been replaced, the fallback key is the exact triple (video, cell, analysis). Approved video-wide Jump Audit decisions match the exact video and analysis type. Conflicting or ambiguous matches reject the restoration atomically. Unmatched decisions are reported in the log rather than guessed. Loading before recursive discovery queues the validated decisions and applies this same matching procedure immediately after the scan. Each applied record preserves its earlier provenance and appends the settings filename and restoration time.

Loading a prior file also restores its recorded jump threshold, which may differ from the current 200-pixel default. The completion dialog states the loaded threshold so the researcher can review it before processing.

Recursive discovery, independent post-processing QC, and repeats

Version 0.8.1 deliberately separates IDtracker execution QC from post-processing QC. The recursive scanner does not read QC/run_status.csv and does not require a prior pipeline approval. It examines every supported IDtracker trajectory under the Firebird folders entered by the researcher. It also reads every run_metadata.json and session_path.txt/session_link.txt found under those folders solely to preserve video, cell, analysis, TOML, and session identity. These metadata links are not approval evidence.

A bare IDtracker session.json normally supplies the video but not the experimental cell. A bare session with no linked cell/analysis identity is retained and reported as IDENTITY_INCOMPLETE; it cannot be processed or approved under a guessed cell. Including the corresponding pipeline run folder as an additional recursive root usually supplies this identity without using its old QC decision.

If linked run metadata has a blank video field, the scanner may recover the video filename from that exact canonical session's session.json:video_paths[0]. This is a direct provenance fallback, not filename guessing. Cell labels must match one uppercase letter followed by one or more digits (for example A1 or C12); malformed metadata such as ACT1 or RERUN remains IDENTITY_INCOMPLETE.

Runs are grouped by the exact (normalized video, cell, analysis) key. All repeats remain visible in the Duplicates tab. Rank 1 is the only run eligible for processing and approval. Ranking is descending by IDtracker session finish timestamp, recorded run timestamp, trajectory modification nanoseconds, attempt index, run index, session path, and trajectory path. The final path tie-breakers make selection deterministic but do not turn a timestamp into biological evidence.

The separate post-processing decision set is UNREVIEWED, APPROVED, or RERUN. Every click writes a new append-only event; earlier decisions are not erased. When a newer duplicate appears, an older approval is not carried forward. The new run begins unreviewed and the approved data file is rebuilt using only current rank-1 sessions whose latest decision is APPROVED.

The rapid-review QC mode operates only on rank-1 processed runs. It opens cached local PDFs from the completed Mac download folder. While the QC table is focused, the spacebar reopens the selected PDF, A writes an APPROVED event, and R writes a RERUN event with the standard reason Rapid PDF QC marked for IDtracker rerun. After either key, the GUI loads the next unreviewed processed PDF. The slower rerun button remains available when a custom human-entered reason is needed.

A RERUN decision is written to sessions_marked_rerun_latest.csv. It does not run IDtracker or modify its files. An APPROVED decision requires an existing per-session processor CSV and adds its animal rows to approved_results_latest.csv. Both files and the append-only decision history live under the configured remote output folder's postprocessing_qc/ directory.

IDtracker trajectory-source priority

The prototype first prefers IDtracker-produced gap-filled files, then uses a raw IDtracker fallback when no gap-filled file exists. The exact priority is:

  1. validated.npy;
  2. without_gaps.npy;
  3. trajectories_wo_gaps.npy (recognized legacy name);
  4. trajectories_without_gaps.npy (recognized legacy name);
  5. trajectories.npy (raw NPY fallback);
  6. trajectories.h5 (raw HDF5 fallback);
  7. trajectories.csv (raw CSV fallback).

The selected category is shown in the GUI and written to trajectory_source_kind. A session is skipped only when no recognized source of any supported type exists or the highest-priority choice is ambiguous.

The prototype performs no additional interpolation. Any coordinates that remain missing in the selected file are counted in the CSV and stated explicitly in the warning column. A raw fallback adds the explicit RAW_IDTRACKER_INPUT warning. Missing coordinates are not filled, and movement gaps are not bridged.

Latency to the displacement threshold

For each individual, the unmodified IDtracker centroid at the exact entry frame is the baseline point. At every global frame in the analysis window, the script calculates straight-line displacement from that fixed baseline.

The reported threshold crossing is the first global frame at which this displacement is equal to or greater than the selected threshold, which defaults to 30 pixels. Latency is the crossing frame minus the analysis start frame. This is net Euclidean displacement from the entry position; it is not cumulative path length and does not use speed, seconds, or a sustained-run rule.

IDtracker animal identity and fight starting side

idtracker_animal_id is the zero-based position on the individual axis of the IDtracker trajectory array. Its values are exactly IDtracker animal 0, animal 1, and so on; this is not a newly inferred biological identity.

For a fight containing exactly two animals, starting_side uses the unmodified x coordinates at the exact approved analysis start frame. The animal with the smaller x coordinate is LEFT and the other is RIGHT. No later frame or average is substituted. Missing start coordinates, equal x coordinates, or an unexpected animal count produce an explicit UNASSIGNED_... value. Non-fight rows contain NOT_APPLICABLE_NOT_FIGHT.

One-frame movement-step QC and total distance

For adjacent finite coordinates, the audit calculates the Euclidean step length. A movement step is rejected when that length is strictly greater than the GUI threshold J. The provisional GUI default is the researcher-selected value of 200 pixels. A value exactly equal to 200 pixels is retained at the default. This threshold is adjustable and has not been established as a biologically validated maximum beetle speed.

The rejected object is the adjacent-frame step, not either endpoint coordinate. The step contributes to no latency chain, total distance, wall/fungus movement distance, social movement distance, post-wake movement metric, or PDF path connection. Both endpoint coordinates remain available for frame-based wall/fungus counts. A later accepted step resumes as a new path segment. Missing coordinates and rejected steps are never bridged.

The per-animal count is therefore named one_frame_jumps_excluded, and one_frame_jump_threshold_px records the applied threshold. The older jump_artifact_coordinate_frames_excluded column remains only for backward schema compatibility and is zero under this step-only rule. Raw IDtracker files are never overwritten and coordinates are never interpolated. The separate read-only Jump Audit may still examine whether large displacements return or persist when proposing a video-wide start change; that diagnostic does not delete coordinates from the processor.

Video-wide disturbance recommendation

Jump destination frames are clustered when consecutive destinations are no more than four frames apart, equivalent to a ±2-frame synchrony tolerance. A cluster is called video-wide only when it affects at least three distinct newest eligible session records and at least half of the eligible records available for that video. Requiring distinct sessions prevents the two animals in one fight from creating a camera-wide classification by themselves.

For a video-wide cluster, let G be the final synchronized disturbance frame. The suggested start is the next 50-frame boundary after G. Equivalently:

suggested start = 50 × ceil((G + 1) / 50).

A recommendation is offered only when the suggested start plus the selected analysis timespan remains within every included trajectory for that video. Cell- or animal-specific jumps remain QC findings and do not produce a video-level start recommendation.

For every pair of consecutive global frames, the script calculates the straight-line distance between the two centroid positions. The column total_distance_px_in_analysis_window is the sum of these step distances from the inclusive start through the inclusive end. A step is included only when both endpoints remain finite after missing-data handling and the step length is at most J. Missing gaps are not interpolated and locations on opposite sides of a gap are not joined. Raw coordinates are never overwritten.

Why pixel distances contain decimals: a straight-line move across both the horizontal and vertical axes is usually not a whole number of pixels. For example, moving one pixel horizontally and one pixel vertically has a straight-line length of approximately 1.414 pixels. IDtracker centroid coordinates may also have subpixel decimal precision. The processor therefore retains the full floating-point distance in calculations and CSV output. Rounding would discard measurement precision and must be used only for optional display, never before distances are summed or analyzed.

Post-wake opportunity-adjusted calculations

The provisional wake frame is the first valid 30-pixel displacement threshold crossing already reported as threshold_crossing_global_frame. Let that frame be C. Post-wake frame summaries include every frame from C through the inclusive analysis end E. Post-wake movement summaries include each adjacent step whose left endpoint is at or after C; thus the first possible movement step is C to C+1.

Let Ai,f be one when both effective coordinates at frames f and f+1 are finite and their step is at most the selected one-frame threshold J, and zero otherwise. The movement opportunity denominator and post-wake distance are

Nstepi = ∑f=CE−1 Ai,f,    Dwakei = ∑f=CE−1 Ai,fsi,f.

The primary opportunity-adjusted movement value is post_wake_distance_px_per_valid_step = Dwake/Nstep. Its units are pixels per valid adjacent movement opportunity, not pixels per elapsed frame. Missing coordinates and rejected >200-pixel steps do not enter the denominator and are not bridged. post_wake_missing_coordinate_frames counts original IDtracker missing frames from C through E. post_wake_jump_excluded_steps counts rejected adjacent steps whose left endpoint is at or after C; the name says “steps” because one jump test applies to one adjacent-frame pair.

Wall frame counts use centroids and wall movement counts/distances use the same accepted-step midpoints described below. post_wake_open_area_proportion is open frames divided by valid post-wake coordinate frames. post_wake_open_distance_px_per_available_step is open-area distance divided by all valid post-wake movement steps, whereas post_wake_speed_px_per_open_step is open-area distance divided only by accepted steps whose midpoint is in the open area. These answer different questions: movement allocated to all available opportunities versus speed conditional on being in the open.

Fight-only fungus outputs use direct complementary masks: on-fungus versus off-fungus. Their “per available step” value divides off-fungus distance by all valid post-wake movement steps; their conditional speed divides by off-fungus steps only. The open-and-off-fungus outputs are calculated from the direct intersection of the wall-open mask and the off-fungus mask, not inferred from their separate totals. The corresponding conditional speed is post_wake_speed_px_per_open_off_fungus_step.

Runtime assertions verify wall inside plus outside step counts and distances, fungus on plus off step counts and distances, and joint-mask subset relationships whenever the relevant ROI partitions pass. If no threshold crossing exists or the exact baseline is invalid, every post-wake numeric is blank, not zero, and post_wake_analysis_status gives the reason. For BA rows, fungus and joint numeric fields are blank and their statuses are NOT_APPLICABLE_NOT_FIGHT.

Fixed 3600-frame-interval post-wake calculations

The post_wake_3600_* columns are a second analysis block; they do not replace the wake-through-end columns above. The processor performs no conversion to seconds. “3600” always means exactly 3600 adjacent-frame intervals, with both endpoints included as 3601 coordinate observations.

For BA animal i, the fixed-window anchor is its own threshold crossing Ci. For a fight containing exactly two animals, the common anchor is the later crossing:

Cboth = max(C0, C1).

Both fight rows therefore use the identical inclusive global range Cboth through Cboth+3600. This begins only after both animals have crossed the wake threshold. The CSV records the rule, global start, global inclusive end, interval count, and observation count. A complete range is required. If a BA animal has no valid crossing, either fight animal has no valid crossing, the fight does not contain exactly two animals, or the inclusive fixed end exceeds the approved analysis end, all affected fixed numeric results are blank rather than zero and post_wake_3600_analysis_status states why.

Within that fixed range, total, wall/open, fight-only fungus on/off and fungus edge-buffer/interior, and direct open-and-off-fungus results use exactly the same equations, accepted adjacent steps, segment midpoints, missing-gap rules, 200-pixel jump rule, and additivity assertions documented for the variable wake-through-end block. Thus, for an available fixed window H,

N3600i = ∑f=HH+3599 Ai,f,    D3600i = ∑f=HH+3599 Ai,fsi,f.

post_wake_3600_distance_px_per_valid_step is D3600/N3600. The denominator can be less than 3600 because original missing coordinates and rejected jumps remove movement opportunities without bridging them.

The fixed block also reports social and turtling screening summaries. Social within-distance frames and animal-specific social movement distance are restricted to the common fight range. A disappearance frame is counted in the fixed block when that frame lies in a disappearance run classified using the full approved analysis-window context; this preserves valid entry or reappearance evidence just outside a fixed boundary. Visible together-separate-together return events are recalculated entirely within the fixed range, so all three phases must be observable there. Turtling candidates are first classified with the documented full-analysis sliding-window detector, including the fight fungus exclusion, and then candidate frames are counted only when they fall inside the fixed range. Its proportion denominator is all originally detected coordinate frames in the fixed range, including real time on fungus where the animal is not counted as turtling.

Thresholds and the social-substitution switch are not duplicated with a post_wake_3600_ prefix. Their existing single-copy CSV columns are the provenance for both the full and fixed calculations. The PDF generator is unchanged by this release.

Primary-ROI wall buffer

The primary arena is roi_list[0] from the canonical session.json. The wall buffer is the portion inside that polygon whose shortest Euclidean distance to any polygon edge is at most the GUI-entered buffer width (default 30 pixels). A valid position farther inward is outside the wall buffer.

Frame classifications use the centroid at the frame. Distance classifications use the midpoint of each valid movement segment. This assigns every ROI-contained segment wholly to either the wall buffer or the interior while preserving its complete length.

The processor checks both identities:

  • wall-buffer frames + interior frames = valid coordinate frames;
  • wall-buffer distance + interior distance = total distance.

spatial_partition_status is PASS only when both hold. A valid centroid or segment midpoint outside the primary ROI causes FAIL_OUTSIDE_PRIMARY_ROI; exact unclassified frame and distance amounts are then written in the warning rather than silently assigned to the interior.

Fight-only fungus ROI and inward edge buffer

Only records explicitly identified as fights are eligible. The fungus is roi_list[1] from the canonical session.json. No second ROI is inferred for BA records. A fight missing this ROI receives NOT_CALCULATED_NO_SECONDARY_ROI and a warning.

A valid centroid is on fungus when it is inside or on the boundary of the secondary polygon. Within that polygon, the inward fungus edge buffer contains points whose shortest Euclidean distance to the polygon edge is at most the GUI-entered width (default 30 pixels). Remaining fungus points are the fungus interior. Movement distance on fungus is classified by the midpoint of each valid adjacent-frame segment, exactly as for the primary ROI.

The processor verifies both identities:

  • fungus edge-buffer frames + fungus-interior frames = frames on fungus;
  • fungus edge-buffer distance + fungus-interior distance = distance on fungus.

Fight-only social distance, movement, and disappearance

These are screening summaries, not confirmed fight labels. They are calculated only when a fight trajectory has exactly two IDtracker animals. One editable social_distance_threshold_px defaults to 60 pixels.

A within-social-distance frame requires valid coordinates for both animals and a Euclidean centroid-to-centroid distance less than or equal to 60 pixels. frames_within_social_distance counts these frames.

For each animal, distance_moved_px_while_within_social_distance sums its adjacent-frame Euclidean movement only when both endpoint frames have both animals visible and within the social distance. A transition into or out of range is not included in this subtotal.

A social disappearance run is a contiguous run in which one specific animal has a missing centroid and the other animal remains visible. It is counted only if:

  1. the run does not start at the first analysis frame;
  2. the immediately preceding frame was within the single 60-pixel social distance; and
  3. the same missing animal reappears with both animals visible before the inclusive analysis window ends.

social_disappearance_frames is animal-specific: each output row counts only qualifying frames when that row's IDtracker animal is missing.

social_return_interaction_events requires a stricter visible sequence: together within 60 pixels, then at least one frame with both animals visible and farther than 60 pixels, then together within 60 pixels again. A missing-only gap is not evidence of separation and cannot create a return event.

Optional social-disappearance substitution

The GUI checkbox Use social disappearance in distance/location calculations defaults to on and can be turned off before processing. When it is on, the visible partner's centroid is copied to the missing animal at each qualifying social-disappearance frame. The substituted series is used for:

  • total_distance_px_in_analysis_window, including valid steps entering, within, and leaving the substituted run;
  • primary-ROI wall-buffer frame and distance calculations; and
  • fight fungus frame and distance calculations.

The switch does not change latency, starting side, frames_within_social_distance, social return-event detection, or the original valid/missing-coordinate counts.

Scientific interpretation. This is a user-selected assumption that the missing beetle occupies the visible partner's centroid during a qualifying overlap. It can create substantial entry and exit movement steps. The CSV and PDF explicitly identify whether it was used and how many frames were substituted for each animal.

In mathematical notation, let pi,f be the original IDtracker coordinate for animal i at frame f, and let j be the visible partner. For a qualifying social-disappearance frame, the effective coordinate used by the enabled calculation switch is

p*i,f = pj,f.

At every other frame, p*i,f = pi,f. Total distance and wall/fungus location calculations use p*; latency, social-event detection, and original missing-data counts continue to use p. When the switch is off, p* = p for all frames.

A rejected jump step is not an original IDtracker missing detection and therefore cannot create social-disappearance evidence. After partner copying, step QC is applied again to the effective calculation series so a copied location cannot introduce a new accepted impossible transition.

The direct remaining unusable-coordinate count is

remaining missing frames = original missing frames − substituted social-disappearance frames.

Provisional tight-loop turtling candidate detector

Interpretation safeguard. IDtracker centroids do not show body orientation. This detector can identify trajectory segments that resemble sustained flailing in a small area, but it cannot prove that a beetle is upside down. Outputs are therefore named turtling candidates and require video or PDF review.

The detector is applied independently to every animal in both BA and fight analyses, using that animal's original IDtracker coordinates. The turtling detector has its own stricter 20-pixel maximum step rule and never connects across missing coordinates or larger steps. Optional social-disappearance substitutions are never used. Every possible consecutive window of W frames is evaluated; the default is 120 frames.

A window qualifies only when all of the following are true:

  1. at least 95% of its coordinate frames are valid;
  2. no valid adjacent-frame step exceeds the editable maximum, default 20 px;
  3. after excluding steps shorter than 1 px as sub-pixel centroid jitter, path length is at least the editable minimum, default 120 px;
  4. the 90th percentile distance from the window's median centroid is between 5 px and the editable maximum, default 35 px;
  5. the sum of absolute wrapped heading changes is at least the editable minimum, default 3 complete rotations; and
  6. net displacement divided by path length is at most the editable maximum, default 0.25.

Every valid-coordinate frame belonging to at least one qualifying window is marked as a candidate. Missing frames are not marked. A candidate event is one contiguous run of marked frames; events are not merged across gaps.

For fight analyses only, each marked frame is then tested against the secondary ROI, roi_list[1]. If the animal's retained centroid is on the boundary or inside that fungus polygon, the frame is removed from the turtling candidate mask. It therefore contributes to neither the reported candidate-frame count, candidate proportion, contiguous-event count, nor the dark-red PDF overlay. BA analyses have no secondary-ROI exclusion.

The reported turtling proportion for animal i is

turtling candidate proportion = fungus-excluded candidate frames / valid detected-coordinate frames in the inclusive analysis window.

Valid frames on the fungus remain in this denominator. They are real biological time during which the animal is not counted as turtling.

If an animal has no valid detected-coordinate frames, the proportion is left blank rather than dividing by zero.

The defaults were provisionally checked against the five supplied PDFs: they identified candidate regions in all three PDFs containing dark-red box annotations and produced zero candidate frames in the two supplied unboxed comparison PDFs. This is preliminary calibration, not general validation. Additional positive and negative examples should be reviewed before using the measure for biological inference.

SLURM batch execution and completeness

The default large-batch mode submits one newest eligible, processable session per SLURM array task. The default throttle is 20 simultaneous tasks. Each task requests one CPU, 4 GB of memory, and two hours; the GUI exposes concurrency, account, partition, time, and memory before submission. The current Firebird defaults are account swat and a blank partition, which delegates partition selection to the cluster.

Each task reads one immutable JSON-manifest item and writes one result CSV, one PDF, and one atomic status JSON. A separate finalizer is submitted with an afterany dependency on the entire array so it always audits the finished batch. It refuses to proceed unless every task status and expected file is successful, then combines the CSVs, checks that the staged PDF count equals the manifest session count, and promotes the CSV and PDF folder as one complete batch. If any task fails, is cancelled, times out, or does not produce its expected files, the finalizer fails without replacing the prior complete outputs.

The GUI log records the array and finalizer job IDs and displays completed task counts while it remains open. The finalizer success marker starts the automatic Mac transfer but does not trigger the final chime. The audible/visible completion alert occurs only after the CSV and verified PDF collection have been downloaded and promoted into the visible local completed-run folder. Combined rows record processing_execution_mode as SLURM_ARRAY or DIRECT_SSH.

PDF audit plots

Each processed session receives one multipage PDF in combined_results_latest_pdfs. Every page prominently identifies the full source video filename and cell; PDF creation stops if either is absent. The QC record ID is also printed when available.

The PDF folder and combined CSV are staged and promoted only after the entire selected batch finishes. A failed or incomplete batch cannot replace the previous complete downloadable batch.

The PDF begins with a combined two-dimensional track map, followed by one two-dimensional page per IDtracker animal and a redesigned three-dimensional page with separate animal panels. Fight PDFs then include a social-distance page: red line segments mark frames within the selected distance and purple line segments mark the visible animal during a qualifying disappearance run. When substitution is enabled, black x markers identify copied partner locations used in calculations. The penultimate page is a translucent wall/fungus buffer map. This colored map is a display raster only; CSV classification still uses the exact point-to-segment geometry described above. Potential turtling paths are shown as thin, semi-transparent, dark-red dashed overlays so the original track remains visible. The metadata page is deliberately last.

The first page includes a large boxed MISSING COORDINATES banner. For each IDtracker animal it shows the original missing-coordinate frame count, the complete inclusive observation count, and the percentage 100 × missing_coordinate_frames_in_window / analysis_frame_observations_inclusive. The banner is display-only QC: it does not filter, substitute, or alter a coordinate. Its color is green below 1%, amber from 1% through less than 10%, and red at 10% or more. The full video filename and cell remain above the banner on page 1 and on every later page.

The third axis is global frame, not seconds. Lines break at original missing coordinates and at every rejected >200-pixel adjacent movement step; the prototype does not interpolate across either. Primary and fungus ROI outlines, exact analysis starts, and threshold-crossing positions are displayed where available. Subtle gray x marks on the primary 2-D pages identify the destination endpoint after a rejected step; the endpoint coordinate itself remains in frame-based classifications.

Missing data and failure behavior

  • If x or y is missing at the approved analysis start frame, latency is not calculated. A later coordinate is never substituted as the baseline.
  • A coordinate that is missing in the selected IDtracker file cannot cross the threshold and is skipped without additional interpolation.
  • A latency crossing is accepted only while the coordinate remains connected to the exact start by a continuous chain of finite adjacent steps at or below the selected jump threshold. Once that chain breaks, later raw coordinates cannot create a wake latency.
  • If no valid point reaches the threshold, status is THRESHOLD_NOT_REACHED; this is distinct from a calculation failure.
  • If the inclusive analysis end frame exceeds the trajectory array length, the session stops with an error. The script does not guess that a shorter array is interval-relative.
  • Output is first written to a .partial file and renamed only after the complete CSV is written.

During the current prototype phase, the canonical per-session file is processed_result_latest.csv and the canonical batch file is combined_results_latest.csv. These names allow a batch to contain clearly labeled gap-filled and raw-fallback sources. Replacement is atomic: the prior complete file remains intact unless the entire new CSV is written, flushed, and successfully renamed. A failed run cannot replace it with partial data.

Automatic Mac output copies

After a complete remote batch is promoted, the GUI automatically downloads the matching CSV and PDF collection to ~/Downloads/IDtracker_postprocessing_results. Both names contain the same processing timestamp. To avoid recursive per-file transfer overhead, Firebird first writes one atomic ZIP archive containing the already-compressed PDFs without applying additional compression. The Mac downloads that single archive, rejects nested, non-PDF, or count-mismatched contents, extracts the verified files, and deletes the temporary ZIP. Downloads are staged under one hidden .partial completed-run folder, which is renamed to its visible final name only after the CSV and every expected PDF are present. The final chime and popup occur after this local rename, not merely after SLURM finishes.

The post-processing QC export creates a separate timestamped folder under ~/Downloads/IDtracker_postprocessing_results/postprocessing_qc/. It contains timestamped copies of approved_results_latest.csv and sessions_marked_rerun_latest.csv, plus an approved_pdfs/ folder copied from the cached completed-run PDF folder. Missing approved PDF copies are reported in approved_pdf_copy_warnings.txt; they are not silently ignored.

Mathematical appendix

This appendix collects the mathematical notation used by the processor. In the definitions below, i identifies an individual, f is a global frame, S is the approved global start frame, W is the requested frame timespan, E is the inclusive global end frame, and T is the displacement threshold in pixels.

Inclusive analysis window

E = S + W

f ∈ {S, S+1, …, E}

The number of frame intervals is E−S=W, while the number of frame observations, because both endpoints are included, is W+1.

Displacement from the entry position and latency

di,f = √[(xi,f−xi,S)² + (yi,f−yi,S)²]

Ci = min { f ∈ [S, E] : di,f ≥ T and every step from S through f is valid and ≤ J }

Li = Ci − S

Here, C is the first threshold-crossing global frame and L is latency in frames and J is the editable one-frame anti-jump threshold, provisional default 200 pixels. The minimum is undefined when no continuously reachable point reaches the threshold; that case is reported as THRESHOLD_NOT_REACHED.

One-frame movement-step rejection

A finite adjacent coordinate pair is rejected from movement calculations when

qi,f = √[(xi,f+1−xi,f)² + (yi,f+1−yi,f)²] > J.

The count of true values of this predicate is one_frame_jumps_excluded. Only the edge (f, f+1) is rejected. Coordinates at both f and f+1 remain available for frame-based classifications; the PDF does not draw the rejected edge. This is why the QC count is a number of steps, not a number of affected coordinate frames.

Consecutive-frame step distance and total distance

si,f = √[(xi,f+1−xi,f)² + (yi,f+1−yi,f)²]

Di = ∑f=SE−1 si,f   for consecutive-frame pairs whose two effective coordinates are finite and whose step is at most J

Each square root can produce a non-integer distance even when the coordinate differences are integers. For example:

√(1² + 1²) = √2 ≈ 1.414213562 pixels

Therefore, total distance is correctly stored as a decimal number. The unrounded accepted step distances are summed; no per-step rounding is performed. At the provisional default J=200 pixels, a 200-pixel step is retained and a step greater than 200 pixels is rejected.

Wall-buffer distance partition

The midpoint used to classify a valid movement segment is

mi,f = ((xi,f+xi,f+1)/2, (yi,f+yi,f+1)/2).

If the midpoint is inside the primary ROI and its shortest Euclidean distance to any ROI boundary segment is less than or equal to the selected wall-buffer width, the complete step length is assigned inside the wall buffer. Otherwise, an ROI-contained midpoint is assigned outside the wall buffer.

Dinside + Doutside = Dtotal

The analogous frame-count partitions are also checked for exact additivity. A point or midpoint outside the primary ROI is reported explicitly and is not silently assigned to either partition.

Starting-side assignment for a two-animal fight

x0,S < x1,S ⇒ animal 0 = LEFT and animal 1 = RIGHT

The assignments are reversed when x1,S < x0,S. Equality or missing values remain unassigned.

Fungus edge-buffer partition

For valid centroid frames whose points lie in the secondary ROI, shortest distance to the secondary polygon boundary assigns each frame to either the inward edge buffer or fungus interior. Valid movement segments are first classified as on fungus when their midpoint lies in the secondary ROI, then partitioned using the same boundary-distance rule.

Fedge + Finterior = Ffungus

Dfungus edge + Dfungus interior = Dfungus

Social distance and return interactions

When both animals are valid, their centroid separation is

qf = √[(x0,f−x1,f)² + (y0,f−y1,f)²].

With the default threshold, a within-range frame satisfies qf ≤ 60 pixels. A missing run from frames a through b is counted for the missing animal only when qa−1 ≤ 60 and that animal is valid again with its partner at frame b+1 ≤ E.

A return interaction event contains a nonempty run between two within-range frames and that run includes at least one frame g where both animals are valid and qg > 60. This enforces the requested together, visibly separate, then together-again sequence.

Tight-loop turtling candidate geometry

For an evaluated window, let dk be each valid adjacent-frame step length. Steps below 1 px are excluded as sub-pixel jitter. The path is

L = Σ dk.

Let m be the component-wise median centroid of valid coordinates in the window. The confinement statistic is

R90 = 90th percentile of ||pf − m||.

For consecutive retained step vectors, heading θk = atan2(Δyk, Δxk). Each heading change is wrapped into [−π, π], and cumulative absolute turning in rotations is

C = Σ |wrap(θk+1 − θk)| / (2π).

Straightness is net displacement divided by path:

Q = ||plast − pfirst|| / L.

The default qualifying inequalities are L ≥ 120 px, 5 px ≤ R90 ≤ 35 px, C ≥ 3 rotations, and Q ≤ 0.25, together with the validity and maximum-step safeguards described above.
