Minimal IDtracker.ai post-processing: version 1

This document describes every calculation performed by processor.py. The script intentionally performs no other behavioral, geometric, or temporal analyses.

Scientific safeguard. A missing interval or an interval starting at global frame 0 is not repaired automatically. The GUI requires a positive, researcher-approved global entry frame before processing. No coordinates are interpolated, smoothed, or carried forward by this prototype. The only optional coordinate replacement is the explicitly enabled social-disappearance substitution documented below. Validated and without-gaps IDtracker files are preferred; a clearly labeled raw IDtracker fallback is used when they are absent.

Analysis window and frame convention

The analysis begins at the researcher-approved global entry frame. The requested timespan, which defaults to 7200 frames, is added to that start to obtain the inclusive global end frame. Both the start and end frames are analyzed.

For example, a start frame of 62 and a requested timespan of 7200 produce an inclusive end frame of 7262. This represents 7200 intervals between frames and 7201 frame observations. The mathematical notation for this convention is collected in the appendix at the end of this document.

Approved-run and repeated-cell selection

The GUI reads the pipeline's authoritative QC/run_status.csv. A run is eligible only when qc_decision is APPROVED or legacy DONE. Folder names, TOML locations, successful completion, and modification times are not interpreted as approval.

Eligible repeats are grouped by the exact triple (video, cell, analysis). The record with the greatest ISO-like date_run is retained. If dates tie, the greater run_index is retained; the metadata path is the final deterministic tie-breaker. The QC record ID, selected run, and source TOML provenance are displayed in the GUI.

IDtracker trajectory-source priority

The prototype first prefers IDtracker-produced gap-filled files, then uses a raw IDtracker fallback when no gap-filled file exists. The exact priority is:

  1. validated.npy;
  2. without_gaps.npy;
  3. trajectories_wo_gaps.npy (recognized legacy name);
  4. trajectories_without_gaps.npy (recognized legacy name);
  5. trajectories.npy (raw NPY fallback);
  6. trajectories.h5 (raw HDF5 fallback);
  7. trajectories.csv (raw CSV fallback).

The selected category is shown in the GUI and written to trajectory_source_kind. A session is skipped only when no recognized source of any supported type exists or the highest-priority choice is ambiguous.

The prototype performs no additional interpolation. Any coordinates that remain missing in the selected file are counted in the CSV and stated explicitly in the warning column. A raw fallback adds the explicit RAW_IDTRACKER_INPUT warning. Missing coordinates are not filled, and movement gaps are not bridged.

Latency to the displacement threshold

For each individual, the unmodified IDtracker centroid at the exact entry frame is the baseline point. At every global frame in the analysis window, the script calculates straight-line displacement from that fixed baseline.

The reported threshold crossing is the first global frame at which this displacement is equal to or greater than the selected threshold, which defaults to 30 pixels. Latency is the crossing frame minus the analysis start frame. This is net Euclidean displacement from the entry position; it is not cumulative path length and does not use speed, seconds, or a sustained-run rule.

IDtracker animal identity and fight starting side

idtracker_animal_id is the zero-based position on the individual axis of the IDtracker trajectory array. Its values are exactly IDtracker animal 0, animal 1, and so on; this is not a newly inferred biological identity.

For a fight containing exactly two animals, starting_side uses the unmodified x coordinates at the exact approved analysis start frame. The animal with the smaller x coordinate is LEFT and the other is RIGHT. No later frame or average is substituted. Missing start coordinates, equal x coordinates, or an unexpected animal count produce an explicit UNASSIGNED_... value. Non-fight rows contain NOT_APPLICABLE_NOT_FIGHT.

Total distance traveled inside the analysis window

For every pair of consecutive global frames, the script calculates the straight-line distance between the two centroid positions. The column total_distance_px_in_analysis_window is the sum of these step distances from the inclusive start through the inclusive end. A step is included only when both x and y are finite at both endpoints. Missing gaps are not interpolated and the locations on opposite sides of a gap are not joined. The warning column reports exactly how many adjacent-frame pairs were excluded.

Why pixel distances contain decimals: a straight-line move across both the horizontal and vertical axes is usually not a whole number of pixels. For example, moving one pixel horizontally and one pixel vertically has a straight-line length of approximately 1.414 pixels. IDtracker centroid coordinates may also have subpixel decimal precision. The processor therefore retains the full floating-point distance in calculations and CSV output. Rounding would discard measurement precision and must be used only for optional display, never before distances are summed or analyzed.

Primary-ROI wall buffer

The primary arena is roi_list[0] from the canonical session.json. The wall buffer is the portion inside that polygon whose shortest Euclidean distance to any polygon edge is at most the GUI-entered buffer width (default 30 pixels). A valid position farther inward is outside the wall buffer.

Frame classifications use the centroid at the frame. Distance classifications use the midpoint of each valid movement segment. This assigns every ROI-contained segment wholly to either the wall buffer or the interior while preserving its complete length.

The processor checks both identities:

  • wall-buffer frames + interior frames = valid coordinate frames;
  • wall-buffer distance + interior distance = total distance.

spatial_partition_status is PASS only when both hold. A valid centroid or segment midpoint outside the primary ROI causes FAIL_OUTSIDE_PRIMARY_ROI; exact unclassified frame and distance amounts are then written in the warning rather than silently assigned to the interior.

Fight-only fungus ROI and inward edge buffer

Only records explicitly identified as fights are eligible. The fungus is roi_list[1] from the canonical session.json. No second ROI is inferred for BA records. A fight missing this ROI receives NOT_CALCULATED_NO_SECONDARY_ROI and a warning.

A valid centroid is on fungus when it is inside or on the boundary of the secondary polygon. Within that polygon, the inward fungus edge buffer contains points whose shortest Euclidean distance to the polygon edge is at most the GUI-entered width (default 30 pixels). Remaining fungus points are the fungus interior. Movement distance on fungus is classified by the midpoint of each valid adjacent-frame segment, exactly as for the primary ROI.

The processor verifies both identities:

  • fungus edge-buffer frames + fungus-interior frames = frames on fungus;
  • fungus edge-buffer distance + fungus-interior distance = distance on fungus.

Fight-only social distance, movement, and disappearance

These are screening summaries, not confirmed fight labels. They are calculated only when a fight trajectory has exactly two IDtracker animals. One editable social_distance_threshold_px defaults to 60 pixels.

A within-social-distance frame requires valid coordinates for both animals and a Euclidean centroid-to-centroid distance less than or equal to 60 pixels. frames_within_social_distance counts these frames.

For each animal, distance_moved_px_while_within_social_distance sums its adjacent-frame Euclidean movement only when both endpoint frames have both animals visible and within the social distance. A transition into or out of range is not included in this subtotal.

A social disappearance run is a contiguous run in which one specific animal has a missing centroid and the other animal remains visible. It is counted only if:

  1. the run does not start at the first analysis frame;
  2. the immediately preceding frame was within the single 60-pixel social distance; and
  3. the same missing animal reappears with both animals visible before the inclusive analysis window ends.

social_disappearance_frames is animal-specific: each output row counts only qualifying frames when that row's IDtracker animal is missing.

social_return_interaction_events requires a stricter visible sequence: together within 60 pixels, then at least one frame with both animals visible and farther than 60 pixels, then together within 60 pixels again. A missing-only gap is not evidence of separation and cannot create a return event.

Optional social-disappearance substitution

The GUI checkbox Use social disappearance in distance/location calculations defaults to off. When it is on, the visible partner's centroid is copied to the missing animal at each qualifying social-disappearance frame. The substituted series is used for:

  • total_distance_px_in_analysis_window, including valid steps entering, within, and leaving the substituted run;
  • primary-ROI wall-buffer frame and distance calculations; and
  • fight fungus frame and distance calculations.

The switch does not change latency, starting side, frames_within_social_distance, social return-event detection, or the original valid/missing-coordinate counts.

Scientific interpretation. This is a user-selected assumption that the missing beetle occupies the visible partner's centroid during a qualifying overlap. It can create substantial entry and exit movement steps. The CSV and PDF explicitly identify whether it was used and how many frames were substituted for each animal.

In mathematical notation, let pi,f be the original IDtracker coordinate for animal i at frame f, and let j be the visible partner. For a qualifying social-disappearance frame, the effective coordinate used by the enabled calculation switch is

p*i,f = pj,f.

At every other frame, p*i,f = pi,f. Total distance and wall/fungus location calculations use p*; latency, social-event detection, and original missing-data counts continue to use p. When the switch is off, p* = p for all frames.

PDF audit plots

Each processed session receives one multipage PDF in combined_results_latest_pdfs. Every page prominently identifies the full source video filename and cell; PDF creation stops if either is absent. The QC record ID is also printed when available.

The PDF folder and combined CSV are staged and promoted only after the entire selected batch finishes. A failed or incomplete batch cannot replace the previous complete downloadable batch.

The PDF begins with a combined two-dimensional track map, followed by one two-dimensional page per IDtracker animal and a redesigned three-dimensional page with separate animal panels. Fight PDFs then include a social-distance page: red line segments mark frames within the selected distance and purple line segments mark the visible animal during a qualifying disappearance run. When substitution is enabled, black x markers identify copied partner locations used in calculations. The penultimate page is a translucent wall/fungus buffer map. This colored map is a display raster only; CSV classification still uses the exact point-to-segment geometry described above. The metadata page is deliberately last.

The third axis is global frame, not seconds. Lines break at coordinates that remain missing in the selected IDtracker file; the prototype does not interpolate them. Primary and fungus ROI outlines, exact analysis starts, and threshold-crossing positions are displayed where available.

Missing data and failure behavior

  • If x or y is missing at the approved analysis start frame, latency is not calculated. A later coordinate is never substituted as the baseline.
  • A coordinate that is missing in the selected IDtracker file cannot cross the threshold and is skipped without additional interpolation.
  • If no valid point reaches the threshold, status is THRESHOLD_NOT_REACHED; this is distinct from a calculation failure.
  • If the inclusive analysis end frame exceeds the trajectory array length, the session stops with an error. The script does not guess that a shorter array is interval-relative.
  • Output is first written to a .partial file and renamed only after the complete CSV is written.

During the current prototype phase, the canonical per-session file is processed_result_latest.csv and the canonical batch file is combined_results_latest.csv. These names allow a batch to contain clearly labeled gap-filled and raw-fallback sources. Replacement is atomic: the prior complete file remains intact unless the entire new CSV is written, flushed, and successfully renamed. A failed run cannot replace it with partial data.

Automatic Mac output copies

After a complete remote batch is promoted, the GUI automatically downloads the matching CSV and PDF folder to ~/Downloads/IDtracker_postprocessing_results. Both names contain the same processing timestamp. Downloads are first staged with hidden .partial names; neither becomes the final timestamped item until both transfers finish.

Mathematical appendix

This appendix collects the mathematical notation used by the processor. In the definitions below, i identifies an individual, f is a global frame, S is the approved global start frame, W is the requested frame timespan, E is the inclusive global end frame, and T is the displacement threshold in pixels.

Inclusive analysis window

E = S + W

f ∈ {S, S+1, …, E}

The number of frame intervals is E−S=W, while the number of frame observations, because both endpoints are included, is W+1.

Displacement from the entry position and latency

di,f = √[(xi,f−xi,S)² + (yi,f−yi,S)²]

Ci = min { f ∈ [S, E] : di,f ≥ T }

Li = Ci − S

Here, C is the first threshold-crossing global frame and L is latency in frames. The minimum is undefined when no valid point reaches the threshold; that case is reported as THRESHOLD_NOT_REACHED.

Consecutive-frame step distance and total distance

si,f = √[(xi,f+1−xi,f)² + (yi,f+1−yi,f)²]

Di = ∑f=SE−1 si,f   for valid consecutive-frame pairs only

Each square root can produce a non-integer distance even when the coordinate differences are integers. For example:

√(1² + 1²) = √2 ≈ 1.414213562 pixels

Therefore, total distance is correctly stored as a decimal number. The unrounded step distances are summed; no per-step rounding is performed.

Wall-buffer distance partition

The midpoint used to classify a valid movement segment is

mi,f = ((xi,f+xi,f+1)/2, (yi,f+yi,f+1)/2).

If the midpoint is inside the primary ROI and its shortest Euclidean distance to any ROI boundary segment is less than or equal to the selected wall-buffer width, the complete step length is assigned inside the wall buffer. Otherwise, an ROI-contained midpoint is assigned outside the wall buffer.

Dinside + Doutside = Dtotal

The analogous frame-count partitions are also checked for exact additivity. A point or midpoint outside the primary ROI is reported explicitly and is not silently assigned to either partition.

Starting-side assignment for a two-animal fight

x0,S < x1,S ⇒ animal 0 = LEFT and animal 1 = RIGHT

The assignments are reversed when x1,S < x0,S. Equality or missing values remain unassigned.

Fungus edge-buffer partition

For valid centroid frames whose points lie in the secondary ROI, shortest distance to the secondary polygon boundary assigns each frame to either the inward edge buffer or fungus interior. Valid movement segments are first classified as on fungus when their midpoint lies in the secondary ROI, then partitioned using the same boundary-distance rule.

Fedge + Finterior = Ffungus

Dfungus edge + Dfungus interior = Dfungus

Social distance and return interactions

When both animals are valid, their centroid separation is

qf = √[(x0,f−x1,f)² + (y0,f−y1,f)²].

With the default threshold, a within-range frame satisfies qf ≤ 60 pixels. A missing run from frames a through b is counted for the missing animal only when qa−1 ≤ 60 and that animal is valid again with its partner at frame b+1 ≤ E.

A return interaction event contains a nonempty run between two within-range frames and that run includes at least one frame g where both animals are valid and qg > 60. This enforces the requested together, visibly separate, then together-again sequence.
